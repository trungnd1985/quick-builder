# Contract: File Storage Providers

**Feature**: `003-media-storage` | **Audience**: anyone implementing a storage provider
(the S3-compatible and Azure Blob providers are next) or storing files from a module

This contract is binding on every provider and every consumer of `IFileStorage`. It
closes 001's exception E-2, which deferred this abstraction until something stored a
file. The design reasoning is in [research.md](../research.md), M-01 to M-05 and M-22.

---

## 1. The interface

`QuickBuilder.Shared.Infrastructure.Storage.IFileStorage`:

| Operation | Signature (shape) | Guarantee |
|---|---|---|
| Write | `Task WriteAsync(StorageKey key, Stream content, CancellationToken ct)` | **Create-only**: throws `StorageKeyExistsException` if the key exists. **All-or-nothing**: if the call throws or is cancelled, the key doesn't exist afterwards, and no reader ever sees a partial object. Reads `content` to the end and doesn't dispose it. |
| Open for read | `Task<StoredFile?> OpenReadAsync(StorageKey key, CancellationToken ct)` | `null` if the key doesn't exist. Otherwise the caller disposes the result. `StoredFile.Content` **must be seekable** (`CanSeek == true`), and reading after a seek returns the bytes at that offset. This is how partial reads work (M-02). `Length` and `LastModifiedUtc` are exact. |
| Exists | `Task<bool> ExistsAsync(StorageKey key, CancellationToken ct)` | No side effects. |
| Delete | `Task DeleteAsync(StorageKey key, CancellationToken ct)` | **Idempotent**: deleting a missing key succeeds. After it returns, `ExistsAsync` is false and `OpenReadAsync` returns `null`. |
| List | `IAsyncEnumerable<StoredFileInfo> ListAsync(string prefix, CancellationToken ct)` | Every committed object whose key starts with `prefix`, in any order. **Never** includes incomplete writes. Streams results: it doesn't load a whole listing into memory. |

Nothing in the interface exposes a file path, a URL, a container name or a provider type.
Consumers must not downcast to a concrete provider.

## 2. Keys

`StorageKey` is the only way to name an object. Its constructor enforces the grammar:

```text
key      = segment *( "/" segment )        ; 1 to 8 segments
segment  = 1*64( %x61-7A / DIGIT / "-" )   ; a-z, 0-9, hyphen
```

- Keys are generated by the system. **They never contain user input**: not file names,
  not slugs, not anything from a request.
- A module's keys **begin with the owning site's id** (`{siteId:N}/…`, Principle V),
  followed by a segment naming the consumer: `media` for this feature.
- A provider may map keys to its own layout (directories, blob names), but it must map
  one key to exactly one location and must stay inside its configured root, container or
  bucket.

## 3. What each provider must do beyond the interface

1. **Health**: implement `IFileStorageHealthCheck.CheckAsync()`. It returns healthy only
   if the back-end can currently be written to and read from, and it answers within 2
   seconds (research M-22). The local provider writes, reads back and deletes a probe
   file at its root.
2. **Configuration**: add its settings under `Storage:<ProviderName>:…`, and become
   selectable through `Storage:Provider` (a case-insensitive name). Validation runs at
   startup (`ValidateOnStart`). An unusable configuration fails startup with a message
   that names the key and the problem.
3. **Incomplete writes**: clean up its own leftovers. The local provider uses
   `.incoming/` plus a cleanup service. S3 uses an abort-incomplete-multipart lifecycle
   rule. Azure discards uncommitted blocks automatically.
4. **Networking**: make **no network call** unless the operator selected that provider
   (constitution Principle II; 003 FR-031).
5. **Tests**: pass the conformance suite (§5) unchanged, plus its own integration tests
   for anything provider-specific.
6. **Justification**: justify any new package in its plan, including its licence
   (Principle XI).

## 4. The local provider

- **Configuration**: `Storage:Local:Path`. It must be absolute and must not be, or be
  inside, the application, content or web roots (checked after resolving links). It is
  created if missing and probed for writability at startup.
- **Layout**: `{Path}/{key}`. Files have mode `0640` on Unix. Temporary files live under
  `{Path}/{first key segment}/.incoming/`, so they are namespaced by site like the files
  themselves (Principle V), and are moved into place atomically. Stale `.part` files
  older than one hour are removed, one first-segment directory at a time, at startup
  and hourly.
- **Containment**: besides the key grammar, the resolved full path is checked to lie
  under `{Path}`.
- **Multiple instances**: they can share the provider only by mounting the same
  directory. The documentation does not advertise this as supported until a shared
  provider exists (spec assumptions; 001 E-4).

## 5. Conformance suite

`tests/QuickBuilder.IntegrationTests/Storage/FileStorageConformanceTests.cs` is abstract.
A provider's test class derives from it and supplies a fresh, empty instance per test.
The suite covers:

| Area | Cases |
|---|---|
| Round trip | Write then read returns identical bytes and length, for 0-byte, 1-byte, 1 MiB and 25 MiB content |
| Create-only | A second write to the same key throws `StorageKeyExistsException`, and the original bytes are unchanged |
| Atomicity | An input stream that throws halfway, and a cancelled token, both leave the key absent and absent from `ListAsync` |
| Partial reads | Seeks to the start, the middle and the last byte return the right bytes. `CanSeek` is true. |
| Missing keys | `OpenReadAsync` is null, `ExistsAsync` is false, and `DeleteAsync` succeeds |
| Delete | Twice in a row succeeds, and so do 8 concurrent deletes of one key. After deletion, read, exists and list all agree that the key is gone. |
| Listing | Only the matching prefix, every committed key exactly once, sizes and times match, and incomplete writes never appear |
| Isolation | Keys under `{siteA}/` never appear when listing `{siteB}/` |
| Grammar | `..`, `/x`, `x/`, upper case, `%2e`, backslashes, empty segments, 65-character segments and nine segments all throw before reaching the provider |
| Concurrency | 20 concurrent writers on distinct keys all succeed, and 20 concurrent writers on one key yield exactly one success |

Adding a case here means every provider must pass it. Removing one needs a spec that
justifies it.
